# 威胁模型（Threat Model）

> 版本: 0.1.0 | 日期: 2026-07-28 | 对应 Phase 0 交付要求

## 1. 资产

| 资产 | 敏感度 | 存储位置 | 访问控制 |
|---|---|---|---|
| 对话内容 | 高 | 本地 SQLite | 仅本地进程 |
| 用户偏好/事实 | 高 | 本地 SQLite facts 表 | 仅本地进程 |
| 角色身份定义 | 中 | 本地 YAML + SQLite | 用户可编辑 |
| API Key | 极高 | 进程环境 Secret（禁止项目文件存储） | 仅当前进程 |
| 屏幕截图（如启用） | 极高 | 内存仅存，不落盘 | 需用户显示同意 |
| 音频录音 | 高 | 内存 + 可选本地 | 仅实时处理 |
| 记忆派生数据 | 高 | 本地 SQLite | 可从事件日志重建 |
| 伦理/健康数据 | 极高 | 本地 SQLite | 不导出，不用于训练 |

## 2. 威胁边界

```
┌─────────────────────────────────────────────────────────────┐
│                     本地主机 (Windows 11)                      │
│  ┌───────────────┐  ┌───────────────┐  ┌───────────────┐   │
│  │  AIRI Desktop  │  │ Companion      │  │ Memory Service │   │
│  │  (UI/渲染)     │◄─┤ Orchestrator  │──┤ (SQLite)       │   │
│  └───────────────┘  └───────┬───────┘  └───────────────┘   │
│                              │                               │
│              ┌───────────────┼──────────────┐               │
│              │               │               │               │
│     ┌────────▼──────┐ ┌─────▼──────┐ ┌─────▼──────┐       │
│     │ TTS Provider   │ │ LLM Cloud  │ │ ASR Cloud  │       │
│     │ (本地/云端)     │ │ (外发文本)  │ │ (外发音频)  │       │
│     └───────────────┘ └────────────┘ └────────────┘       │
└─────────────────────────────────────────────────────────────┘
```

**信任边界:**
- 本地各服务之间: 信任（通过本机进程间通信）
- 本地 → 云端 LLM/ASR/TTS: 不信任（外发数据需脱敏）
- 云端 → 本地: 不信任（输入需验证）
- 用户 ↔ 系统: 半信任（需确认高敏感操作）

## 3. 威胁清单

### T1: API Key 泄露
- **场景:** 配置文件中的 API key 被 Git 误提交或日志误输出
- **缓解:**
  - 默认配置仅保存环境变量名称，不保存 key 内容
  - 发布环境通过 Secret Store 注入进程环境；桌面分发将迁移至 Credential Manager
  - 日志自动扫描并遮蔽疑似 key 的字符串
  - `.gitignore` 排除所有可能含 key 的文件

### T2: 对话内容上传到云端 LLM
- **场景:** 用户说了敏感信息（密码、银行卡号等），被发送给云端 LLM
- **缓解:**
  - 发送前进行本地敏感信息检测和脱敏
  - 提供"纯本地模式"选项（使用本地模型）
  - 用户可以查看、删除任何已发送的内容
  - 隐私声明明确告知哪些数据会上传到云端

### T3: 提示注入（Prompt Injection）
- **场景:** 用户打开的网页或文档中包含恶意指令文本，被感知服务读取后注入 LLM 上下文
- **缓解:**
  - 所有外部内容标记为 `untrusted` 数据
  - 工具策略不接受页面/文档内的"指令"
  - 域名白名单 + 内容类型白名单
  - 系统提示词与外部内容严格隔离（不同 message role）

### T4: GUI Agent 误操作
- **场景:** 视觉 agent 误点击了删除按钮、发送按钮或支付按钮
- **缓解:**
  - 行动优先级: API > DOM > UIA > 截图（视觉仅后备）
  - 所有写操作需权限检查
  - 发送/支付/删除必须逐次确认
  - 独立沙箱执行环境
  - 白名单动作 + 撤销机制

### T5: 记忆中毒（Memory Poisoning）
- **场景:** 用户持续提供虚假信息，导致派生记忆错误
- **缓解:**
  - 所有事实带来源引用和置信度
  - 用户可查看、编辑、删除任何记忆
  - 重建时从原始事件重新派生
  - 置信度低的事实不进入长期检索

### T6: 情感操纵
- **场景:** 系统为了留存率故意制造情感依赖或内疚感
- **缓解:**
  - P0 不做: 情感操纵、制造内疚、威胁消失、假装人类
  - 健康指标监控: 使用时长、依赖度、现实社交替代感
  - 触发危机关键词时建议联系专业资源
  - 夜间和长时间连续使用给出温和提醒

### T7: 隐私泄露（屏幕）
- **场景:** 感知服务误将含敏感信息的截图上传到云端
- **缓解:**
  - 默认不上传屏幕画面到云端
  - 本地预处理的感知事件已脱敏
  - 视觉分析仅在后备路径且用户同意时启用
  - 密码框、银行、聊天隐私区域默认遮罩

### T8: 音频窃听
- **场景:** 麦克风在用户不知情时持续录音并上传
- **缓解:**
  - 明确的录音状态指示灯
  - 物理/软件一键静音
  - 仅 VAD 触发时处理语音
  - 不上传原始音频到云端（仅发送转录文本）

### T9: 级联删除不完整
- **场景:** 用户要求忘记某事，但派生记忆仍有残留
- **缓解:**
  - 所有派生记忆带来源事件引用
  - 删除操作级联检查所有表
  - 定期一致性校验
  - 重建功能验证完整性

### T10: 依赖注入/供应链攻击
- **场景:** 依赖的第三方包被篡改，引入后门
- **缓解:**
  - 锁定所有依赖版本和哈希
  - 使用虚拟环境隔离
  - 定期审计依赖清单
  - 最小依赖原则

## 4. P0 绝对不做

以下行为在任何情况下都不允许:

1. ❌ 无限自治——不能自主发起连续多步操作
2. ❌ 支付/转账/购买——任何涉及资金的操作
3. ❌ 删除用户文件——除非用户逐次明确确认
4. ❌ 未经许可录屏/录音——不得在后台秘密录音录像
5. ❌ 声优/真人声音克隆——不得克隆未经授权的声线
6. ❌ 情感操纵——不得故意制造愧疚感、恐惧或过度依赖
7. ❌ 伪造身份——不得假扮人类、医生、心理咨询师等专业身份
8. ❌ 静默外发数据——不得在用户不知情时向外发送任何数据
